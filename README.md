# Баня Чибис — готовый сайт для GitHub Pages

Адаптивный одностраничный сайт на русском языке. Не требует сервера, базы данных, npm или платных сервисов. HTML, CSS, JavaScript и все фотографии находятся в архиве. Сторонние шрифты, аналитика и формы сбора данных не подключены.

## Посмотреть сайт

Распакуйте архив и откройте `index.html` в браузере. Основное содержимое сайта доступно без интернета; встроенная Яндекс Карта и переходы в Яндекс Карты требуют подключения к интернету.

Адрес и координаты проверены в Яндекс Картах. Кнопка «Построить маршрут» открывает навигацию к метке. Если появится отдельная карточка бани, можно заменить `map_url` ссылкой на неё.
3. Проверьте цену и условия: 6 000 ₽ за 3 часа; компания до 6 человек; баня целиком; работает круглосуточно по предварительной записи; без предоплаты и залога; дубовый веник в подарок. Взяты условия из вашего описания.

Формат настроек:

```json
{
  "site_url": "",
  "phone": "",
  "phone_display": "",
  "exact_address": "",
  "map_url": ""
}
```

- `phone` — российский номер: `+7`, затем 10 цифр, без пробелов и скобок.
- `phone_display` — тот же номер в удобном для чтения виде. Если пусто, выводится `phone`.
- `exact_address` — полный адрес. Если пусто, остаётся известный адрес до сельского поселения и название деревни.
- `map_url` — HTTPS-ссылка на дом или карточку бани. Сейчас указана проверенная карточка дома 9а.
- `map_latitude` и `map_longitude` — координаты метки, сейчас 55.919306 и 49.138196. Они взяты из карточки адреса на Яндекс Картах, используются для встроенной карты и маршрута. Метка указывает адрес дома; отдельный вход в баню уточняйте по телефону.
- `site_url` — окончательный HTTPS-адрес сайта с путём репозитория, если он есть. При публикации через GitHub Actions адрес подставится автоматически, поэтому поле можно оставить пустым.

Телефон и адрес уже внесены в настройки и готовый HTML. На десктопе номер расположен в разделе контактов, на мобильном дополнительно доступна закреплённая кнопка «Позвонить и записаться». Встроенная карта видна прямо на странице, а кнопка карты открывает адрес дома в Яндекс Картах.

## Публикация на GitHub Pages — рекомендуемый способ

1. Создайте репозиторий в аккаунте владельца бани, например `banya-chibis`. Для бесплатной публикации обычно используют публичный репозиторий.
2. Загрузите **содержимое** распакованного архива в корень репозитория. Файл `index.html` должен оказаться на первом уровне. Сохраните структуру `assets`, `scripts` и `.github/workflows`.
3. Проверьте, что файл `.github/workflows/pages.yml` действительно появился в репозитории. Не загружайте сам ZIP вместо содержимого.
4. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Откройте вкладку **Actions**, выберите процесс **Publish Banya Chibis to GitHub Pages** и нажмите **Run workflow**, если он не запустился после загрузки. Основная ветка должна называться `main`.
6. Дождитесь успешного завершения. Ссылка появится в **Settings → Pages** и в результате публикации во вкладке Actions.

Сборка сама подставляет фактический адрес GitHub Pages в canonical, Open Graph и sitemap.xml, учитывая путь репозитория. Она собирает только файлы сайта в `dist`, поэтому настройки и скрипты не попадают в опубликованную папку.

Для загрузки всех файлов также можно использовать GitHub Desktop: создать или клонировать репозиторий, скопировать содержимое архива, сделать Commit и Push. Передавать друг другу пароль от аккаунта не требуется: владелец может пригласить вас в репозиторий как участника.

## Публикация без GitHub Actions

Сайт можно опубликовать как обычную статическую страницу. После заполнения `settings.json` выполните из папки проекта:

```bash
python3 scripts/build.py --url https://USERNAME.github.io/REPOSITORY/
```

Замените `USERNAME` и `REPOSITORY` на реальные значения. Windows: вместо `python3` можно использовать `py`.

В папке `dist` появится готовый сайт. Загрузите **содержимое dist** в корень репозитория и выберите **Settings → Pages → Deploy from a branch → main → / (root) → Save**.

Если Python недоступен, исходный `index.html` вместе с `assets`, `404.html`, `robots.txt` и `.nojekyll` уже можно публиковать. Телефон и адрес уже присутствуют в HTML. Для SEO-ссылок с окончательным URL потребуется сборка либо ручное редактирование HTML. Поэтому способ с Actions удобнее.

Для обновления файлов прямо в корне исходного проекта:

```bash
python3 scripts/build.py --output . --url https://USERNAME.github.io/REPOSITORY/
```

При переходе на свой домен пересоберите сайт с новым окончательным адресом. Не создавайте несколько индексируемых копий сайта с разными canonical.

## Что сделано для SEO

- Статический HTML: описание бани, цена, адрес и ответы на вопросы читаются без JavaScript.
- Русский язык, индивидуальные title и description, один видимый H1, последовательные H2/H3.
- Локальные формулировки: баня на дровах, Макаровка, Высокогорский район, Татарстан, рядом с Казанью. Без списка повторяющихся ключевых слов.
- JSON-LD LocalBusiness с ценой и услугой; FAQPage повторяет реальные видимые вопросы и ответы. Без выдуманных отзывов и рейтингов. Часы работы — круглосуточно. Добавлены проверенные координаты адреса дома.
- Canonical, Open Graph, изображение для соцсетей, sitemap.xml и ссылка на sitemap в robots.txt **после сборки с реальным URL**. Пока адрес неизвестен, фиктивные ссылки не добавлены.
- Все 16 исходных фото включены в галерею. Есть описательные alt, размеры, WebP и уменьшенные версии. Главное фото загружается приоритетно; остальные — лениво.
- Адаптивная вёрстка, доступная навигация с клавиатуры, увеличение фото, стрелки, Escape, свайпы, учёт уменьшения анимации.
- Собственная страница 404 с запретом индексации. На GitHub Pages отсутствующие адреса обслуживаются штатным механизмом 404.

Структурированные данные не гарантируют расширенный сниппет. SEO-подготовка не гарантирует позиции в поиске. После публикации добавьте сайт в Яндекс Вебмастер и Google Search Console и отправьте sitemap.xml. Когда создадите карточки организации, укажите в них одинаковые название, телефон, адрес и URL сайта.

Примечание: поисковые роботы читают robots.txt в корне домена. У проектного GitHub Pages вида `USERNAME.github.io/REPOSITORY/` файл `/REPOSITORY/robots.txt` не управляет всем доменом. Sitemap можно отправить напрямую через панели вебмастеров. На отдельном домене robots.txt будет лежать в корне.

## Изменение текстов и фотографий

- `index.html` — тексты, цена, секции, FAQ.
- `assets/style.css` — оформление и мобильная версия.
- `assets/app.js` — меню, галерея, фильтры и просмотр фото.
- `settings.json` — контакты и URL.
- `scripts/build.py` — статическая сборка и SEO. В начале `data` перечислены названия фото, alt, порядок и категории. При сборке галерея пересоздаётся из этого списка.
- `assets/photos/01.webp` … `16.webp` — все прикреплённые фотографии в исходном порядке по имени файла. Файлы `*-small.webp` — уменьшенные версии для галереи. Оригинальные загрузки не изменялись.

После изменения цены найдите все её упоминания в `index.html` и обновите также `priceRange` и `makesOffer.price` в `scripts/build.py`. После изменения FAQ разметка FAQPage обновится автоматически при сборке.

Видимый сайт не содержит формы бронирования: GitHub Pages не обрабатывает заявки на сервере. Основной контакт — прямой звонок владельцу.
